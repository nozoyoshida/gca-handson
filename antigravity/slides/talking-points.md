## Ch.0: 環境準備（15分）

### 進行形式
- ブラウザ（Chrome）で各自のワークステーションを起動 → ブラウザ IDE が開く
- ターミナルで **Antigravity CLI を認証**（ヘッドレス OAuth）：
  - 表示された URL をブラウザで開き、払い出されたコードをターミナルに貼付
  - GEAP の **project + region** を指定
- 続けて **`gcloud auth login`**（Ch.5 のデプロイ用）→ **認証は2系統あると明示**
- `git clone` → `starter/` フォルダを開く → ターミナルで `python app.py` → **ウェブプレビュー**で GUI を確認

### キーメッセージ
- **認証は2系統**：CLI の認証 = **GEAP**（コーディング用）、`gcloud` の認証 = **Cloud Run**（デプロイ用）。混同しやすいので最初に整理する
- 理想は**管理者がカスタムイメージに CLI と gcloud をプリインストール**しておくこと（当日のセットアップ時間を最小化）

### 進行のコツ
- 初回のワークステーション起動は時間がかかる → 開始前に各自起動を始めてもらう
- 認証で詰まる人が出やすい章。全体を止めず、トラブルシューティング表で個別フォロー

## Ch.1: Antigravity CLI の基本（10分）

### キーメッセージ
- CLI は **TUI**（ターミナル UI）。基本フローは **計画 → 承認 → 実行 → 検証**
- 権限モデルは **allow / deny / ask**。何を自動許可するかを意識する
- **Artifacts はリポジトリ内のファイル + ターミナル出力**。検証は **curl + ウェブプレビュー**で行う（ブラウザ録画は IDE 側の機能で、CLI では想定しない）

### 進行形式
- この章は操作感を掴むことが目的。**app.py を汚さない**ため、提案された計画は**却下**するか、実行してしまったら **`git restore`** で元に戻す
- 「コード変更は Ch.2 以降で行います」と案内

## Ch.2: Context Engineering（16分）

### キーメッセージ
- **AGENTS.md が最もレバレッジの高いファイル**（Rules を記述、毎タスク自動で読み込まれる）
- **Workflow**（例: `/code-review`）で再利用可能な手順を定義できる
- AGENTS.md は AI が「実際に読む」オンボーディング文書と考える

### Before/After のポイント
- **同一プロンプトを `git restore` で揃えて比較**する（AGENTS.md なし → あり）
- 出力品質が劇的に変わることを強調する

## Ch.3: Agentic Coding（16分）

### キーメッセージ
- 「コードを書いてもらう」から「**目標を伝えて計画をレビューする**」へのパラダイムシフト
- **計画レビュー → 承認 → 実行**のワークフローを体験することが目的
- AGENTS.md + Agentic な実行 = 一貫した出力品質

### 実装する機能
- **対応履歴機能**：`responses` テーブル + GET/POST エンドポイント + `ticket_detail.html`
- 検証は **curl + ウェブプレビュー**で**内部メモバッジ**が表示されることを確認

### 注意事項
- 生成 AI の出力は**毎回異なる** → 参加者の画面が講師と違っても正常
- 期待と違ったら「ワークフローの体験が目的」と伝え、`completed/` の参照コードを見せる

## Ch.4: セキュア開発（13分）

### キーメッセージ
- 流れは **検出（OWASP）→ 修正 → ルール化**
- ルール化 = **AGENTS.md にセキュリティ最優先を明記** + **`/code-review` Workflow を強化**
- 「見つけて直す」だけでなく「ルール化して自動チェック」まで行うのがポイント

### 補足紹介のポイント
- **CLI の権限モデル**：allow / deny / ask。`--dangerously-skip-permissions` は強力だが**乱用しないよう注意**を促す
- **GEAP のガバナンス**：Agent Identity / Agent Registry / Agent Gateway、**Model Armor**（入出力チェック）
- いずれもハンズオンでは触らない、紹介のみ

### 注意事項
- Ch.2 の **AGENTS.md の効果で一部の脆弱性が既に修正済み**のことがある → 「これが Context Engineering の効果です」と説明

## Ch.5: Cloud Run デプロイ（16分）

### キーメッセージ
- **実装(Ch.3) → セキュア化(Ch.4) → デプロイ(Ch.5) を同じ AI と一気通貫で**
- ワークステーションからそのまま**サーバーレスに出荷**できることを体感してもらう

### デプロイ手順
- ワークステーションのターミナルで：
  `gcloud run deploy <サービス名> --source . --region asia-northeast1 --allow-unauthenticated`
- （**Cloud Run MCP** を使う方法もあるが**要検証**）
- 払い出された **公開 URL をブラウザで開いて確認**

### 本番化の肝（必ず強調）
- **init_db() をモジュール読み込み時に呼ぶ**：gunicorn は `__main__` を通らないため、import 時に DB が初期化されないと Cloud Run で 500 エラーになる（`CREATE TABLE IF NOT EXISTS` で冪等に）
- **`0.0.0.0` と環境変数 `PORT`（既定 8080）で待受**、本番サーバーは **gunicorn**
- **SQLite は Cloud Run では揮発**：コールドスタートで消える。デモのみ。本番は **Cloud SQL / Firestore**

### 進行のコツ
- デプロイは **Cloud Build のビルド待ちで数分**。待ち時間に `completed/` のデプロイ成果物（`Dockerfile` / `Procfile` / `.gcloudignore` / `app.py` の `init_db()` の位置）を見せる
- 権限不足が出たら**附録 A**（管理者セットアップ）の手順で対応

## Wrap-up（4分）

### 3つのキーメッセージ

1. **Context Engineering が AI 活用の成否を決める（76% → 83%）**
   - コンテキスト改善でレビュー精度が向上。エージェントの失敗の多くは「モデルの失敗」ではなく「コンテキストの失敗」
   - 今日体験したように、AGENTS.md の小さな追加で同じプロンプトでも出力品質が劇的に変わる

2. **AI 生成コードは人間の約 1.7 倍の問題を含む → 開発者は設計・レビュー・判断へ**
   - AI 生成コードは人間比 **1.7 倍の問題**、約 45% にセキュリティ欠陥という調査結果
   - AI は開発者を「コードを書く人」から「**設計し、レビューし、判断する人**」に変える

3. **攻撃者も AI を使う → 防御に自動チェックとガバナンスを**
   - AI サイバー攻撃は増加、脆弱性の公開から悪用までの期間は近年わずか数日に短縮
   - `/code-review` の自動チェックや GEAP のガバナンスは「あれば便利」ではなく必須の防御手段

### 締めのメッセージ
- **アイデア → 計画 → 検証 → デプロイを一気通貫**で。AI 駆動開発は「コードを書く」だけでなく「出荷する」まで伴走する

## トラブルシューティング

| 問題 | 対処 |
|------|------|
| ワークステーションが起動しない / 遅い | 初回起動は時間がかかる。コンソールから再起動する |
| CLI 認証のコードが貼れない | ヘッドレス OAuth。表示 URL をブラウザで開き、コードをターミナルに貼付する |
| ウェブプレビューが開かない | ポート（5000 / 8080）を指定し `https://PORT-<ws>.<cluster>.cloudworkstations.dev`。アプリが `127.0.0.1` でなく `0.0.0.0` で待受しているか確認 |
| CLI コマンド名 / サブコマンドが違う | 公式ドキュメントで確認（要検証項目） |
| gcloud デプロイで権限不足 | 管理者がユーザーに `roles/run.admin`・`iam.serviceAccountUser`・`cloudbuild.builds.editor`・`artifactregistry.writer` を付与（附録 A） |
| Agent の出力が毎回違う | 正常。`completed/` を参照 |
| デプロイ後 500 エラー | `init_db()` が import 時に呼ばれていない。`completed/` の `app.py` を参照 |
| データが消える | SQLite は Cloud Run で揮発（仕様）。本番は Cloud SQL / Firestore を使う |
