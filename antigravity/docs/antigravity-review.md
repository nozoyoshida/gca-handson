## 2. コンテンツの強みと教育的効果

1. **Context Engineering (AGENTS.md) の重要性**:
   - Ch.2 にて、`AGENTS.md` の有無で同じプロンプトの出力精度がどう変わるかを比較する構成は、コンテキスト設計（指示の与え方）の重要性を伝える上で最も効果的です。
2. **本番環境への配慮（Ch.5）**:
   - `gunicorn` を経由した起動時に SQLite テーブルが作成されない（`__main__` が走らない）問題と、その対策（モジュールロード時に `init_db()` を冪等に呼び出す）について実地で対策を打たせる部分は、実務的で極めて実践的です。
3. **セキュリティのルール化**:
   - 脆弱性を単に見つけて直すだけでなく、`AGENTS.md` や `Skill`（自動コードレビュー）にセキュリティルールとして定着させる流れ（Ch.4）は、開発の持続可能性を意識した良い設計です。

## 3. 推奨される改善点・注意点

### ① ウェブプレビューに関する補足
- **現状**: ローカルで動かしたアプリへのアクセスとして、プレビュー URL を使用する旨が記載されています。
- **改善案**: Cloud Workstations のプレビュー機能は、アプリがリッスンしているポート番号に基づいて URL が生成されます。受講者が混乱しないよう、「起動するポート番号（例: 5000）とプレビュー URL のポート番号が一致している必要があること」を明記すると、トラブルシューティングがスムーズになります。

### ② settings.json のマッチングルールの具体化
- **現状**: Module 1 で `allow` や `deny` に `command(git)` などを記載する説明があります。
- **改善案**: トークン単位での前方一致（例: `command(git)` は `git commit` や `git push` にマッチするが、`github` という別のコマンドにはマッチしない）について、簡単な補足があると理解が深まります。

### ③ サンドボックス（nsjail）のホスト要件
- **現状**: サンドボックスを有効化して nsjail でプロセスを隔離する演習があります。
- **改善案**: クラウド環境（特にコンテナベースの Workstations）では、ホスト側で必要なシステムコール権限や namespace 作成権限が制限されていると、nsjail が起動エラーを起こす場合があります。管理者向けのセットアップガイド（附録 A）に、カスタムイメージ構築時のセキュリティ特権要件を注記しておくことを推奨します。

## 4. 成果物コード（completed/app.py）の分析

完成版として提供されている `completed/app.py` は、以下の点で非常に優れた実装となっています。

- **セキュリティ対策**:
  - 全クエリにプレースホルダーを使用し、SQL インジェクションを確実に防止。
  - HTML タグを除去する `strip_html_tags` および文字列長制限をかけたバリデーション関数の徹底。
- **冪等性の確保**:
  - `init_db()` 内のテーブル作成に `CREATE TABLE IF NOT EXISTS` を使い、サンプルデータは既存レコードがない場合のみ挿入する設計。これにより、アプリのコールドスタートやコンテナの水平スケール時にもデータが安全に初期化されます。
