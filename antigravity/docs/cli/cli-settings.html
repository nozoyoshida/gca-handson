設定（settings.json）

出典: antigravity.google/docs/cli-settings（公式ドキュメントの日本語要約）

永続的な設定の保存、キーボードショートカットのカスタマイズ、ターミナルの表示バッファの切り替え、実行時の CLI パラメータ上書きの管理を行います。

設定（preferences）のセットアップ

Antigravity CLI は、ユーザー設定を最小限かつ将来互換性のある JSON 設定プロファイルとして保存します。

設定ファイルの場所

永続的な設定は、プレーンな JSON 形式で次の場所に保存されます。

~/.gemini/antigravity-cli/settings.json

CLI は スパース永続化（sparse persistence） を採用しており、システムのデフォルト値と異なる値だけをディスクに書き込みます。これにより設定ファイルはクリーンかつ最小限に保たれ、将来のアップデートとの完全な前方互換性が維持されます。

対話型の設定パネル

生の JSON ファイルを開かずに、アクティブなターミナルセッション内で直接設定を編集するには、次の手順を実行します。

  1. プロンプトパネルで /config（またはエイリアスの /settings）と入力し、Enter を押します。
  2. フルスクリーンの 設定エディタオーバーレイ（Settings Editor Overlay） が開きます。
  3. ↑ / ↓ で利用可能なオプション間を移動します。
  4. ハイライトされたパラメータ上で Enter を押すと、状態の切り替え、またはテキスト入力フィールドの表示が行われます。
  5. Esc を押すと変更を保存してエディタを閉じます。

コマンドラインによる上書き

CLI のコマンドフラグを使うことで、個々のターミナルセッションに限って永続的な設定を一時的に上書きできます。

agy --sandbox=false --notifications=false

上書きフラグが有効な場合、対話型の /config メニューでは、変更された設定の横に警告インジケータが表示されます。

! Tool Permission: strict (overridden by command flag)

これらのセッション中もディスク上の永続値を編集することは可能ですが、CLI はセッションを閉じるまでアクティブな実行時フラグの上書きを優先します。

表示（レンダリング）モード

TUI は、ターミナルの機能と接続レイテンシに応じて、2 つの表示モードのいずれかで動作します。

モード設定値概要
Alt-screen モード always ターミナルの代替バッファを使って専用の表示画面を開き、没入感のある独立したアプリ風インターフェースを構成します。
Inline モード never 標準の stdout パイプライン内に出力を逐次レンダリングします。
自動検出 default 環境を自動検出し、高機能なローカルシェルでは Alt-Screen、SSH 上や非対話セッションでは Inline モードに切り替えます。

Alt-screen モード（always）

  • 主な特徴: 統合スクロールバック、マウスホイールによるスクロール対応、カスタム描画のスクロールバー、終了時のクリーンなターミナル状態の復元。
  • 適した用途: 高機能なターミナルエミュレータ（iTerm2、Ghostty、WezTerm など）での標準的なローカル開発セッション。

Inline モード（never）

  • 主な特徴: セッション履歴全体をエミュレータのネイティブなスクロールバックバッファ内に保持し、マウス入力をキャプチャせず、標準的なコマンド出力とシームレスに併存します。
  • 適した用途: リモートの SSH ターミナル、tmux や screen などのターミナルマルチプレクサ、低帯域のリモートセッション。
メモ：アダプティブレンダリング
Alt-Screen モードを default に設定すると、TUI が環境を自動検出します。高機能なローカルシェルでは Alt-Screen をデフォルトとし、SSH 経由や非対話セッションで実行している場合は Inline モードへフォールバックします。

カスタムステータスラインとターミナルタイトル

高度な TUI 環境連携のために、アクティブなメトリクスの切り替えや、カスタムスクリプトによる動的なステータスバーの生成・ターミナルウィンドウタイトルの変更を行えます。

  • ステータスラインのカスタマイズ: ステータスインジケータパネルの管理方法と、カスタム整形されたステータスラインシェルスクリプトの構築方法を解説します。
  • ターミナルタイトルのカスタマイズ: ウィンドウタイトル出力の切り替え方法と、ライブのエージェント状態をウィンドウヘッダーへ送り込む方法を解説します。

キーバインドの設定

TUI のほぼすべてのキーボードショートカットは、キーを特定のワークスペースコマンドにマッピングすることでカスタマイズできます。

キーバインドファイルの場所

カスタムマップは、メインの設定プロファイルと同じ場所に保存されます。

~/.gemini/antigravity-cli/keybindings.json

フォーマットとカスタマイズ

この JSON 構造は、1 つの TUI コマンドアクションをホットキーシーケンスの配列にマッピングします。

{
  "cli.clear_screen": ["ctrl+l"],
  "prompt.insert_newline": ["shift+enter", "ctrl+j"],
  "edit.open_editor": ["ctrl+g"]
}

デフォルトのホットキーを完全に無効化するには、そのアクションを空の配列 [] にマッピングします。JSON スキーマが不正または無効な場合、CLI は該当するアクションについてシステムデフォルトにフォールバックし、残りの有効なマッピングを読み込みます。

注意：保護されたキー
cli.exit（Ctrl+D / Ctrl+C）や cli.enter（Enter）といった重要なナビゲーションショートカットはシステムによって保護されており、無効化できません。

デフォルトへの復元

すべてのキーをシステムデフォルトに戻すには、キーバインドプロファイルを削除するだけです。

rm ~/.gemini/antigravity-cli/keybindings.json

次のステップ

環境の設定が完了したら、セキュリティ制御と拡張オプションを確認しましょう。

  • 権限とサンドボックス: 安全な実行封じ込め境界を管理します。
  • プラグインとスキル: 独自のカスタムスキルを作成し、レガシープラグインをインポートします。
  • CLI リファレンス: すべての設定オプション、コマンド、デフォルトのキーマップを一覧できるクイックリファレンスにアクセスします。
