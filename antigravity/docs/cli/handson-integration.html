ハンズオンでの agy 活用ポイント（洗い出し）

対象: antigravity/docs/handson-guide.html／根拠: 公式 CLI ドキュメント要約

既存の Antigravity ハンズオン各章に、agy CLI のスラッシュコマンドとベストプラクティスを自然に組み込める箇所を洗い出しました。あわせて、現行ガイドの記述が公式ドキュメントと食い違う「要修正点」も整理しています。

1. 章別 活用マップ

章自然に使える agy の機能・コマンドねらい
Ch.0 環境準備 ?（コマンド一覧）／/config（設定パネル：verbosity を low に）／/model（モデル選択）／/permissions（自律レベル選択） 最初に CLI の全体像とコマンド体系を掴ませる。ノイズ低減と権限の初期設定をここで済ませる。
Ch.1 CLI 基本 @（ファイルパス補完）／!（ターミナル直実行）／Esc（ターン中断）/esc esc（入力クリア）／/rewind(/undo)／/fork／/resume 「計画→承認→実行→検証」に加え、中断・巻き戻し・分岐という CLI ならではのセッション操作を体験させる。app.py を汚さない運用にも直結。
Ch.2 Context Engineering AGENTS.md（ワークスペース直下、起動時に自動読込）／@ でコンテキスト付与／「探索→計画→実行」のフェーズ分割 AGENTS.md は公式ベストプラクティスそのもの。Before/After 比較に最適。コードレビュー自動化は Skill（.agents/skills/code-review.md → /code-review）として表現する（下記 3 章）。
Ch.3 Agentic Coding 探索→計画→実行（実装計画アーティファクト）／検証ループ（テスト/ curl を agent に実行させる）／/agents・/tasks（進捗監視）／/rewind（失敗時の巻き戻し） 単発実装でも「先に計画を出させてレビュー→承認→実行→検証」を徹底。検証ループは公式の最重要プラクティス。
Ch.4 セキュア開発 権限エンジン（permissions の allow/deny/ask、例: deny: command(rm -rf), command(sudo)）／ターミナルサンドボックス（enableTerminalSandbox / proceed-in-sandbox） 最良の親和性。「安全な AI 開発」という章テーマと、agy の権限/サンドボックスが直結。脆弱性の修正に加え、エージェント自身の実行を安全に縛る体験を足せる。
Ch.5 Cloud Run -p ワンショット（例: コミットメッセージ生成を git hook 化）／検証ループ（デプロイ後に公開 URL を curl）／command(gcloud …) の権限制御 「実装→出荷」を自動化文脈に拡張。デプロイ後の動作確認を agent の検証ループに組み込む。

2. 公式ベストプラクティスと章の対応

ベストプラクティス（公式）ハンズオンでの活用箇所
検証ループを作る（テスト/ビルドを agent に実行させ反復）Ch.3 実装直後／Ch.5 デプロイ後の curl 確認
探索 → 計画 → 実行 のフェーズ分割Ch.3 の中心。Ch.4 修正でも「まず脆弱性を説明させる→計画→修正」
コンテキストを与える（@、ctrl+v でスクショ添付）Ch.1〜4 の @app.py。UI 不具合のデバッグ例に ctrl+v を追加可
ルールファイル（GEMINI.md / AGENTS.md）Ch.2 の中心（現行どおり AGENTS.md でOK）
権限を構造化（request-review / proceed-in-sandbox / strict）Ch.0 で初期設定、Ch.4 で深掘り
セッション管理（esc / /rewind / /fork / /resume）Ch.1 で体験
自動化（agy -p、並列サブエージェント）Ch.5 の git hook 例／発展ハンズオン（M2・M3）

3. 現行ガイドの要修正点（公式ドキュメントとの相違）

背景
既存ガイドはプレビュー段階の推測（要確認 表記）を含んでいました。公式 CLI ドキュメントの取得により、以下は事実に基づいて修正可能になりました。
該当箇所現状（推測）公式準拠の修正案
Ch.2 / Ch.4 / 附録 B のコードレビュー自動化 .agents/workflows/code-review.md を置いて /code-review で起動 修正済み: 正しくは Skill として表現する。.agents/skills/code-review.md に Frontmatter（name: / description:）付きの Markdown を置くと、自動的に /code-review スラッシュコマンドとして登録される（全ワークスペース共有なら ~/.gemini/antigravity-cli/skills/ に配置）。先の .agents/workflows/ というパスは誤りだったが、/code-review 自体は有効。
Ch.0 の GEAP 認証 agy login ＋ agy config set project/location 公式 CLI ドキュメントは Google アカウントでのサインイン（/logout でログアウト）を示し、プロジェクト/リージョンを指定する CLI フラグは記載されていない。エンタープライズ（GEAP）固有のプロジェクト紐付けは引き続き 要確認 として扱い、断定を避ける。
Ch.4 補足の「URL 許可リスト」 「要確認」と記載 確定: 権限アクション read_url(domain) / execute_url(domain) が該当。既定は Ask。これでプロンプトインジェクション対策を具体化できる。
附録 B チートシート 推測コマンド中心 実在コマンドへ更新済み（/config /permissions /model /agents /tasks /skills /mcp /rewind /fork /resume、@ ! ?、ctrl+g/ctrl+v/ctrl+k、-p、permissions/enableTerminalSandbox）。

4. 推奨アクション

  • ハンズオンガイドの先頭・各章から本 CLI リファレンスへリンクし、詳細はそちらへ誘導（実施済み）。
  • 附録 B チートシートを実在コマンドへ更新（実施済み）。
  • コードレビュー自動化を Skill（.agents/skills/code-review.md）へ再構成（実施済み。completed/・templates・各章に反映）。
  • 「権限/サンドボックスでエージェント実行を安全に縛る」等の発展テーマは 発展ハンズオン（M1〜M7）として実装済み。
