プラグイン

出典: antigravity.google/docs/cli-plugins（公式ドキュメントの日本語要約）

エージェントの機能を拡張し、サードパーティの拡張バンドルをインストールし、カスタムワークフロースキルをパッケージ化し、Model Context Protocol（MCP）サーバーと連携します。

拡張性モデル

Antigravity CLI は無制限のカスタマイズを前提として設計されています。プラグイン（Plugins）と呼ばれる構造化されたパッケージモジュールをインストールしたり、スキル（Skills）と呼ばれるローカルな Markdown のブループリントを作成したりすることで、共有エージェントハーネスを拡張できます。

これらのカスタマイズにより、エージェントは専用の独自コマンドにアクセスし、ドメイン固有のサブエージェントを呼び出し、カスタマイズされたスタイル制約を参照できるようになります。

Antigravity プラグイン

プラグインは、カスタムスキル、バックグラウンドのサブエージェント、リンティングルール、Model Context Protocol の定義、イベントフックを、単一のデプロイ可能なアセットにパッケージ化した、名前空間付きのバンドルです。

プラグインのファイルシステム構造

プラグインをインストールまたはインポートすると、CLI はバンドルのファイルをグローバル設定パス内にステージングします。

~/.gemini/antigravity-cli/plugins/<plugin_name>/

準拠したプラグインは、次のレイアウトを含みます。

~/.gemini/antigravity-cli/plugins/<plugin_name>/
├── plugin.json                 # Required package marker file
├── mcp_config.json             # Optional Model Context Protocol servers
├── hooks.json                  # Optional pre/post tool event hooks
├── skills/                     # Optional specialized skills directory
├── agents/                     # Optional subagent definition templates
└── rules/                      # Optional custom codebase rules files

CLI サブコマンドによるプラグイン管理

CLI は、拡張機能を管理するための plugin（または複数形の plugins）サブコマンドのパイプラインを提供します。

  • インストール済みプラグインの一覧表示: アクティブなパッケージと、ロードされたコンポーネントを表示します。 
    agy plugin list
  • ローカルまたはリモートのプラグインのインストール: パッケージディレクトリをローカルプロファイルにステージングします。 
    agy plugin install /path/to/local/plugin
  • プラグインの無効化／有効化: アセットを削除せずに、プラグインのツールを一時停止します。 
    agy plugin disable <plugin_name>
agy plugin enable <plugin_name>
  • プラグインのアンインストール: パッケージディレクトリを削除し、レジストリをクリーンアップします。 
    agy plugin uninstall <plugin_name>

エージェントスキル

スキルは、宣言的で人間が読める Markdown ファイルであり、専門的なエンジニアリングタスクに向けた明示的な指示プロトコル、スクリプト、対象リソースを記述します。

登録されると、スキルは自動的に TUI 内のスラッシュコマンドに変換され、手動で呼び出せるようになります（例: /refactor-ui と入力）。

ローカルなワークスペーススキルの作成

Git リポジトリと一緒に保持される、ワークスペース固有のスキルをデプロイするには次の手順に従います。

  1. プロジェクトのルートに .agents/skills/ という名前のディレクトリを作成します。
  2. その中に、.md 拡張子の Markdown ファイル（format-tests.md など）を作成します。
  3. スキルのフロントマターメタデータを定義します。 
    ---
name: format-tests
description: Standardize and re-format Python unittest assertions
---
  4. メタデータの下に、エージェントへの明示的な指示を記述します。このディレクトリで agy を実行すると、スキルがコンパイルされ、プロンプトボックスで /format-tests が利用可能になります。

グローバルスキルの共有

ワークステーション上のすべてのワークスペースでスキルを共有するには、対象の Markdown ファイルをグローバル設定パス内に配置します。

~/.gemini/antigravity-cli/skills/

このディレクトリ内のあらゆる Markdown スキルは、任意のディレクトリで agy を起動するたびに、グローバルなスラッシュコマンドとして自動的にインポートされます。

フックの管理

フックは、実行の直前または直後にエージェントのアクションをインターセプトします。これは、自動的なプリフライトチェックや生成後のフォーマット（ファイル書き込み後の prettier 実行など）を行うのに役立ちます。

フックは、プラグインの hooks.json 内で定義するか、メインの settings.json ファイル内で構成します。ロードされてアクティブなすべてのフックは、TUI で次のように入力して確認できます。

/hooks

Model Context Protocol（MCP）

Model Context Protocol は、基盤モデルがローカル API、ファイルパーサー、カスタム開発ツールと安全に連携できるようにするオープンスタンダードです。

Antigravity CLI は、ローカルプロセスとリモートホストの MCP サーバー構成の両方をサポートします。

MCP マネージャーへのアクセス

プロンプトパネルで /mcp と入力して Enter を押すと、対話的な MCP マネージャーオーバーレイ（MCP Manager Overlay）が開きます。このパネルでは次のことができます。

  • アクティブ、切断、ロード中のサーバーのライブステータスリングを表示する。
  • サーバー構成を手動で再読み込みしたり、接続ログを確認したりする。

グローバルおよびワークスペースのサーバー構成

従来のセットアップとは異なり、Antigravity は MCP の定義を、専用の簡潔な構成に分離します。

  • グローバルサーバー設定: ~/.gemini/antigravity-cli/mcp_config.json で構成します。
  • ワークスペースローカル設定: アクティブなプロジェクト内の .agents/mcp_config.json で構成します。
{
  "mcpServers": {
    "sqlite-explorer": {
      "command": "node",
      "args": ["/usr/local/bin/sqlite-mcp-server.js"],
      "env": {
        "SQLITE_DB_PATH": "/var/data/app.db"
      }
    }
  }
}
注意
リモート接続スキーマ: リモートの SSE または WebSocket ベースの MCP 接続を宣言する場合は、serverUrl フィールドを定義する必要があります。url や httpUrl などの従来のフィールドはサポートされていません。

次のステップ

既存の構成を Gemini CLI から移行する方法や、接続の異常をトラブルシューティングする方法を学びます。

  • Gemini CLI からの移行: 従来の拡張機能や構成の変換を迅速に行います。
  • トラブルシューティング: ターミナルのフックエラー、ロックアウト、ネットワーク障害を解決します。
  • 権限とサンドボックス: カスタムプラグインや MCP サーバーの周囲にセキュリティ封じ込めリングを構成します。
