agy CLI を活かす追加ハンズオン案

根拠: 公式 CLI ドキュメント要約（features / best-practices / permissions / sandbox / subagents / plugins）

agy CLI の「並列サブエージェント」「権限＆サンドボックス」「プラグイン/スキル」「非対話実行（-p）」「セッション操作（/fork 等）」といった特徴を主役にした、追加ハンズオンのネタ案です。既存の「お問い合わせ管理 API」題材を流用できます。各案に ねらい / 使う機能 / 流れ / レベル・所要 を付けました。

案 A. 並列サブエージェントで大規模リファクタ／監査

ねらい: 1 つの会話をブロックせず、複数の作業を並列に走らせる「エージェントの司令塔」体験。

  • 使う機能: 並列サブエージェント、/agents パネル、/tasks、高速承認 ctrl+k／テレポート ctrl+j
  • 流れ: 「全関数に docstring を付与」「危険な SQL をパラメータ化」「各エンドポイントに最小テストを追加」を同時にサブエージェントへ依頼 → /agents で進捗監視 → 承認待ちは ctrl+k で即承認 → 主画面では別作業を継続。
  • レベル・所要: 中級 / 20分

案 B. 権限＆サンドボックスで「安全なエージェント運用」

ねらい: Ch.4（セキュア開発）の発展。コードの安全性だけでなくエージェント実行そのものの安全性を設計する。

  • 使う機能: ~/.gemini/antigravity-cli/settings.json の permissions（allow/deny/ask、優先順位 Deny > Ask > Allow）、ターミナルサンドボックス（enableTerminalSandbox / proceed-in-sandbox）
  • 流れ: deny: command(rm -rf), command(sudo), command(curl .*) と allow: command(git), command(npm run (build|lint|test)) を設定 → わざと「一時ファイルを掃除して」等の曖昧/危険な指示を出し、ブロック/確認が働くことを確認 → proceed-in-sandbox で未知コマンドが nsjail 隔離下で動くことを体験。
  • レベル・所要: 中級 / 20分

案 C. -p ワンショットで CI / Git フック自動化

ねらい: 対話だけでなく、エージェントをシェルパイプライン/自動化に組み込む。

  • 使う機能: 非対話実行 agy -p "..." --cwd $(pwd)
  • 流れ: prepare-commit-msg フックで agy -p "Review this git diff and draft a conventional commit message" を実行しコミットメッセージ草案を生成 → さらに「変更点からリリースノートを生成」「PR 説明文を作成」へ展開。
  • レベル・所要: 中級 / 15分

案 D. スキル／プラグインでチーム規約をパッケージ化

ねらい: 自分用の手順を再利用可能なスキルとして束ね、チームに配布する。

  • 使う機能: /skills、プラグイン（~/.gemini/antigravity-cli/plugins/<name>/ に plugin.json / skills/ / agents/ / rules/ / mcp_config.json / hooks.json）
  • 流れ: 「お問い合わせ API のコードレビュー」スキルを作成（セキュリティ＋規約チェックの手順を定義）→ /skills から呼び出し → プラグイン化してチーム配布、起動時に自動ロードされることを確認。
  • レベル・所要: 中〜上級 / 25分

案 E. MCP サーバー連携で外部システムを操作

ねらい: エージェントから外部ツール（DB・監視・クラウド）へ安全に接続する。

  • 使う機能: /mcp、権限 mcp(server/tool)
  • 流れ: Cloud Run の MCP サーバー等を /mcp で接続 → 「このアプリをデプロイして URL を教えて」と依頼し、MCP ツール経由で実行 → mcp(...) 権限で実行可能ツールを限定。
  • レベル・所要: 上級 / 20分（※接続先の準備が必要）

案 F. 視覚デバッグ（スクリーンショット添付）

ねらい: フロントの表示崩れを、画像を見せて直してもらう。

  • 使う機能: プロンプトへのメディア貼付 ctrl+v（PNG/JPEG/動画など）
  • 流れ: チケット詳細画面の CSS をわざと崩す → 崩れた画面のスクショを ctrl+v で添付し「この崩れを直して」と依頼 → 修正後、ウェブプレビューで確認。
  • レベル・所要: 初〜中級 / 15分

案 G. /fork で実装方針 A/B を比較

ねらい: 不確実な設計判断を、会話を分岐して実験的に比較する。

  • 使う機能: /fork（分岐）、/resume（/switch、戻る）、/rewind（/undo、巻き戻し）、Esc（中断）
  • 流れ: 「全文検索を LIKE で実装」と「SQLite FTS で実装」を /fork で別セッションに分けて試す → 良い方を採用、もう片方は /resume で破棄 → 失敗したら /rewind で安定点へ。
  • レベル・所要: 中級 / 20分
組み合わせのおすすめ
既存ハンズオン（Ch.0〜5）に対して、案 B（権限/サンドボックス）を Ch.4 の発展として、案 C（-p 自動化）を Ch.5 の発展として差し込むと、追加コストが小さく効果的です。半日ワークショップにするなら 案 A・D を独立セッションとして追加してください。
